# 位姿生成策略快速对比

## 问题诊断总结

### 系统瓶颈分析

| 阶段 | 当前表现 | 瓶颈类型 | 影响度 |
|------|---------|---------|--------|
| 视觉估测 | quality_score 0.4-0.8 | 精度有限（±3-5cm） | 中 |
| 候选生成 | 固定笛卡尔网格 | 分布不均，无可达性预评估 | **高** |
| 候选评估 | 直接规划尝试 | 无快速筛选，每次耗时1-2s | **高** |
| 排序策略 | 简单距离权重 | 未考虑 IK 可达性、碰撞风险 | 中 |
| 失败处理 | 线性后退策略 | 松弛约束后仍失败率高 | 中 |
| **总体** | **12s，成功率60%** | **候选生成和评估** | **决定性** |

## 当前 vs. 改进方案对比

### 候选生成策略

#### 当前（笛卡尔固定网格）

```
┌─────────────────────────┐
│ 目标位姿（from 视觉）   │
└────────────┬────────────┘
             │
             ↓
    生成固定网格候选
    ├─ X: center.x ± 5mm  (3 个)
    ├─ Y: center.y ± 5mm  (3 个)
    ├─ Z: center.z ± 10mm (3 个)
    └─ Roll: ±10°         (5 个)
    
    候选总数: 3×3×3×5 = 135 ~ 270 个
    
    问题：
    • 固定在笛卡尔坐标，不关心圆柱轴方向
    • 分布密度与工作空间形状无关
    • 无法动态调整范围
    • 无可达性预评估
```

#### 改进（极坐标自适应采样）

```
┌──────────────────────────────────┐
│ 视觉约束建立                      │
│ ├─ center, axis_normal           │
│ ├─ quality_score → uncertainty   │
│ └─ axis_uncertainty_m, ...       │
└────────────┬─────────────────────┘
             │
             ↓
    快速工作空间可达性评估 (0.3s)
    ├─ 快速 IK 检查 (3 个初值)
    ├─ 关节配置成本评估
    └─ 碰撞距离评估
             │
             ↓
    自适应极坐标采样
    └─ 初始阶段 (即时)
       ├─ 轴向: [-2cm, 0, +2cm]   (3 层)
       ├─ 方位: 0°, 45°, ..., 315° (8 个)
       └─ 候选数: 24 个
       
       失败后触发扩展阶段 1
       ├─ 轴向: [-8cm, 0, +8cm]   (3 层)
       ├─ 方位: 0°, 30°, ..., 330° (12 个)
       └─ 新增候选: ~36 个
       
       若继续失败，扩展阶段 2
       ├─ 轴向: [-15cm, 0, +15cm] (3 层)
       ├─ 方位: (16 个)
       └─ 新增候选: ~48 个
    
    优势：
    • 几何意义清晰（环绕圆柱）
    • 初期评估快速（候选少）
    • 自动向高可达区域扩展
    • 参数可动态调整
```

### 评分系统对比

#### 当前方案

```cpp
score = feasible_cost_pos_weight_ * distance_to_reference
      + feasible_cost_ori_weight_ * angular_distance
      + feasible_cost_roll_weight_ * |roll_offset|
```

**问题**：
- 仅考虑位置距离和方向距离
- 完全忽视 IK 可达性、碰撞风险
- 无法区分"看起来接近但 IK 无解"和"稍远但高度可达"

#### 改进方案

```cpp
composite_score = 0.35 * reachability_score    // IK可达性(快速评估)
                + 0.25 * ik_quality_score      // 配置空间成本
                + 0.25 * collision_score       // 碰撞距离倒数
                + 0.05 * smoothness_score      // 与历史解的连通性
                + 0.10 * vision_confidence     // 视觉质量
```

**优势**：
- 多维度综合评价
- 可达性权重最高（0.35），直接面向规划成功
- IK 质量和碰撞安全性能够筛选劣质候选
- 可配置的权重，支持场景适配

### 执行流程对比

#### 当前流程（串行尝试）

```
接收 target_pose (来自 vision_to_arm_transform)
    ↓
生成 270 个候选位姿 (~50ms)
    ↓
for i in 1..8:
  │
  ├─ plan(candidates[i])  [1-2 秒]
  │  ├─ 成功? → 执行 + 结束 ✓
  │  └─ 失败? → 继续下一个
  │
  └─ i==8 且全失败?
      └─ 尝试松弛约束 (1-2 秒)
         ├─ 成功? → 执行 ✓
         └─ 失败? → 放弃 ✗

总耗时：8-16 秒（依赖规划速度）
成功率：60%（低）
```

#### 改进流程（分阶段自适应）

```
接收 target_pose + quality_score
    ↓
建立 CylinderPoseConstraint (~10ms)
    ├─ center, normal, uncertainty
    └─ 质量分数驱动的不确定度
    ↓
【初始阶段】快速评估 + 尝试
    ├─ 快速 IK 可达性评估：24 个候选 (~300ms)
    ├─ 综合评分 + 排序 (~10ms)
    ├─ 尝试前 3 个候选规划 (~4.5s)
    │  ├─ 若有成功 → 执行 ✓ (耗时: 4.8s)
    │  └─ 全失败 → 进入扩展
    │
    ├─【扩展阶段1】更大搜索范围
    │  ├─ 轴向范围扩至 ±8cm，方位角增至 12
    │  ├─ 评估新候选 (~400ms)
    │  ├─ 尝试前 4 个 (~6s)
    │  ├─ 若有成功 → 执行 ✓ (耗时: 11.1s)
    │  └─ 全失败 → 进入扩展2
    │
    └─【扩展阶段2】极限搜索范围
       ├─ 轴向范围扩至 ±15cm，方位角增至 16
       ├─ 若有成功 → 执行 ✓ (耗时: 16+s)
       └─ 全失败 → 激进约束降级

期望总耗时：4-8 秒（大多数情况）
期望成功率：95%+ （自适应扩展保证）
```

## 关键改进点解释

### 1. 极坐标采样的几何优势

**为什么围绕圆柱轴线采样更优？**

当前笛卡尔网格：
```
      Z
      ↑
      │   target
      ├─●  (X, Y, Z)
      │ ╱╲╲
      ├──┼──→ X
      │  ╱
      ├─●─●  (±5mm grid)
     O│
      ├──→ Y
```

问题：网格固定在全局坐标，不关心圆柱轴方向
- 若圆柱竖直（轴沿 Z），网格合适
- 若圆柱倾斜，网格就不适配了

改进的极坐标：
```
      圆柱轴线 (normal)
      ↓↓↓↓↓↓
      ┌─────────┐
      │    ◯    │  <- 圆柱顶部
      │ 8 个采样点
      │  ╱  ╲
      │ ╱    ╲
      │⚫ ⚫  ⚫  <- 观测环（距离固定）
      │ ╲    ╱
      │  ╲  ╱
      │  ◯    │  <- 圆柱底部
      └─────────┘
      
      ±轴向偏移：研究不同高度
```

优势：
- 自动适应圆柱的任意方向
- 观测点始终围绕圆柱（符合"扫描"的语义）
- 易于参数化扩展（轴向范围、方位角数量）

### 2. 快速可达性评估的必要性

**为什么不能直接规划评估？**

```
规划成本：1-2 秒/候选
快速IK评估：0.05-0.1 秒/候选

当规划 8 个候选：8×1.5 = 12 秒
若先用 IK 快速筛选：
  • 评估全部 24 候选：24×0.07 = 1.7 秒
  • 只规划前 4 个：4×1.5 = 6 秒
  • 总计：7.7 秒（节省 35%）
  
当失败率高时（60%），预评估节省更大：
  • 若初始 24 个中 22 个 IK 无解，可提前筛除
  • 只有 2 个是真正需要规划的
  • 相当于从 270 候选中直接找到 2 个可行解
```

### 3. 历史学习的价值

**为什么需要记录成功案例？**

```
当前：每次都从头规划，前次的经验完全丢失

改进：记录成功的位姿和对应评分
  ├─ 发现"低评分但高成功"的模式
  │  └─ 调整权重（如增加 vision_confidence 权重）
  ├─ 记录哪个阶段最有效
  │  └─ 优化扩展策略
  └─ 追踪难易场景
     └─ 适应性强化

示例：
  如果发现当 quality_score < 0.5 时，
  扩展阶段 1 的成功率异常高（>80%），
  则可以在质量低时直接跳到扩展阶段 1
```
