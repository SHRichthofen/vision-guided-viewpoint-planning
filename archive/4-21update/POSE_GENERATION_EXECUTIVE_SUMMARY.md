# 改进位姿生成策略 - 执行摘要

**日期**：2026年4月21日  
**项目**：基于视觉的圆柱底部扫描系统  
**问题**：规划耗时长（12s）+ 成功率低（60%）  
**方案**：分层位姿生成与自适应候选策略

---

## 问题诊断（5 分钟阅读）

### 当前系统流程

```
相机 → 视觉检测 → 坐标变换 → 目标位姿生成 → 路径规划 → 执行
                                    ↑
                          【问题发生处】
                       - 候选网格固定
                       - 无可达性评估
                       - 盲目尝试规划
```

### 三个核心问题

| # | 问题 | 当前表现 | 根本原因 |
|---|------|---------|---------|
| **1** | 采样失败 | 成功率 60% | 候选生成不关注工作空间；IK 约束过严 |
| **2** | 耗时长 | 12 秒平均 | 每个候选都要规划（1-2s）；无快速筛选 |
| **3** | 不适应 | 固定网格 | 笛卡尔网格不适应圆柱的任意方向 |

**根本原因**：将位姿生成问题视为"纯距离最小化"，忽视了机械臂工作空间的几何性质和 IK 可达性。

---

## 改进方案（5 分钟阅读）

### 核心思路

从 **被动应对** → **主动构建**

```
当前：生成目标 → 网格搜索 → 规划失败 → 松弛约束 → 规划失败 → 放弃
改进：生成目标 → 评估可达性 → 自适应采样 → 优先排序 → 高效规划
```

### 五层递进改进

#### 【第1层】视觉约束建立
- 从视觉质量分数 (quality_score) 推导位置/方向不确定度
- 不是硬性拒绝低质量检测，而是"扩大容许范围"
- **耗时**：<10ms | **收益**：可量化置信度

#### 【第2层】工作空间可达性评估
- 快速 IK 检查（0.1s timeout），用 3 个初值探针
- 计算可达性评分 [0, 1]
- 完全无解的目标提前筛除，避免浪费规划时间
- **耗时**：<100ms/候选 | **收益**：提前发现不可达

#### 【第3层】极坐标自适应采样 ⭐ 核心创新
- 构建围绕圆柱轴线的局部坐标系 (U, V, W)
- 初始：轴向 3 层 × 方位 8 方向 = **24 个候选**（vs. 270）
- 失败时自动扩展：轴向±8cm，方位12方向 → 36 个新候选
- 继续失败再扩展：轴向±15cm，方位16方向 → 48 个新候选
- 无需手动调参，自动逐级扩展搜索范围
- **收益**：初期评估快速，失败时能自动扩大范围

#### 【第4层】多维度综合评分
```
score = 0.35*reachability + 0.25*ik_quality + 0.25*collision 
      + 0.05*smoothness + 0.10*vision_confidence
```
- 不仅考虑距离，还考虑可达性、成本、碰撞、连通性
- 权重可配置，支持不同场景适配
- **收益**：有效排序候选，高分优先尝试

#### 【第5层】实时反馈与学习
- 记录成功的位姿和对应评分
- 若发现低评分却成功的案例，自动调整权重
- 逐次改进策略，适应变化的环境
- **收益**：长期自优化

## 常见问题解答

**Q1: 为什么要用极坐标而不继续优化笛卡尔网格？**

A: 极坐标有三个根本优势：
   1. 几何意义清晰（围绕圆柱采样，符合场景）
   2. 参数化程度高（轴向范围、方位角数量可动态调整）
   3. 与工作空间形状无关（自动适应圆柱方向）
   
   笛卡尔网格在这些方面都很硬性。

**Q2: 快速 IK 评估会不会漏掉有效候选？**

A: 不会。快速评估的目的是排除"完全无解"的候选。
   如果 searchPositionIK(0.1s timeout) 找不到解，
   也意味着完整规划几乎肯定也找不到，
   所以这个筛选不会造成假阴性。

**Q3: 参数太多了，怎么调优？**

A: 参数确实多，但大部分有默认值：
   - 权重：推荐 [0.35, 0.25, 0.25, 0.05, 0.10]
   - 轴向范围：初始 ±2cm，扩展1 ±8cm，扩展2 ±15cm
   - 方位角：初始 8，扩展1 12，扩展2 16
   
   这些都是基于常规 6 轴机械臂的经验值。
   若实际表现不佳，只需微调 1-2 个关键参数。

**Q4: 这个方案能解决所有问题吗？**

A: 不能。改进方案主要针对"候选生成和排序"阶段。
   它假设基础 IK 求解和规划算法工作正常。
   如果问题根本上源于：
   - 手眼标定误差过大（>5cm）
   - 机械臂关节可用性差（反复卡顿）
   - URDF 模型不准确
   
   则需要先解决这些根本问题。
