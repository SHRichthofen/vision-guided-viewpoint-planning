# 质量分数为 0 问题分析与修复

**问题时间**: 2026-04-20 16:15  
**现象**: 节点不断输出"质量分数过低"警告，分数多为 0.0 或 0.143

```
[WARN] 目标 391 质量分数过低 (0.143 < 0.5), 拒绝发布
[WARN] 目标 391 质量分数过低 (0.000 < 0.5), 拒绝发布
...
```

---

## 一、根本原因分析

### 问题1：轴比判断过严格 ⚠️

**原代码**:
```python
axis_ratio_min = 0.15
axis_ratio_max = 0.95

if axis_ratio < axis_ratio_min or axis_ratio > axis_ratio_max:
    q_axis = 0.0  # 立即给0分！
```

**问题**:
- 圆柱在**斜视（30-60°）**时，轴比可能 < 0.15（很扁）
- 圆柱在**几乎垂直视图**时，轴比可能 > 0.95（接近圆形）
- 这两种都是**合法的观测场景**，但却被判为0分
- `q_axis = 0.0` 会导致整体 quality_score 大幅下降（权重20%）

### 问题2：残差计算导致大幅减分 ⚠️

**原代码**:
```python
q_residual = max(0.0, 1.0 - residual / residual_max)
# 如果 residual = 3.0, residual_max = 3.0
# → q_residual = 0.0
```

**问题**:
- 边缘拟合有噪声是正常的，±3px是合理的容差
- 但当残差达到阈值时，直接给0分太严格
- 应该是**渐进式衰减**而非阶跃下降

### 问题3：质量门控阈值过高 ⚠️

**原配置**:
```python
QUALITY_MIN_PUBLISH = 0.5  # 需要至少50分才能发布
```

**问题**:
- Phase A1-A2的质量评分是**新增的严格约束**
- 初始参数应该是**保守（宽松）**的，逐步调优
- 0.5的阈值对早期测试太严格

### 问题4：加权组合中残差权重过高 ⚠️

**原代码**:
```python
quality_score = (
    0.20 * q_rim_area +
    0.25 * q_coverage +
    0.35 * q_residual +    # ← 最高权重！
    0.20 * q_axis
)
```

**问题**:
- 残差最容易受噪声影响（图像质量、边缘检测参数）
- 给它35%权重意味着**拟合不完美立即扣大分**
- 但实际上，即使残差0.5-1.0，位姿仍然可用

---

## 二、修复方案

### 修复1：轴比判断改为宽松模式 ✅

**新代码**:
```python
# 有效范围更宽：0.0 ~ 1.0（而非严格的0.15~0.95）
if axis_ratio <= 0.0 or axis_ratio > 1.0:
    q_axis = 0.0  # 完全无效
elif axis_ratio < 0.1:  
    # 视角很斜，但仍可用，给0.4-0.7分
    q_axis = 0.4 + (axis_ratio / 0.1) * 0.3  
elif axis_ratio > 0.95:
    # 几乎是圆形（垂直看），给0.7-1.0分
    q_axis = 0.7 + (1.0 - axis_ratio) * 3.0  
else:
    # 正常范围 [0.1, 0.95]，越接近0.5越好
    target_ratio = 0.5
    deviation = abs(axis_ratio - target_ratio)
    q_axis = max(0.4, 1.0 - deviation / target_ratio * 0.6)  # 最低保留0.4
```

**逻辑**:
- `axis_ratio < 0.1`: 保证 ≥ 0.4 分（可用但扣分）
- `axis_ratio > 0.95`: 保证 ≥ 0.7 分（角度接近垂直，更清晰）
- **最关键**：永远不因为轴比值就给 0 分

### 修复2：残差改为渐进衰减 ✅

**新代码**:
```python
# 残差 = residual_max 时得分0.3，而非0.0
q_residual = max(0.0, 1.0 - residual / residual_max * 0.7)
```

**效果**:
| residual | 公式结果 | 原代码 | 差异 |
|----------|---------|--------|------|
| 0.0 px   | 1.0     | 1.0    | - |
| 1.0 px   | 0.77    | 0.67   | +0.10 |
| 2.0 px   | 0.53    | 0.33   | +0.20 |
| 3.0 px   | 0.30    | 0.0    | +0.30 ⬆️ |

### 修复3：降低发布门控阈值 ✅

**原**: `QUALITY_MIN_PUBLISH = 0.5`  
**新**: `QUALITY_MIN_PUBLISH = 0.3`

**理由**:
- Phase A 是新增的严格评估机制
- 初期应该更**宽松**，观察实际效果
- 0.3 意味着：只要有基本可用的观测就能发布
- 可逐步升高到 0.4-0.5，根据实际需求微调

### 修复4：重新调整权重组合 ✅

**原配置**:
```python
0.20 * q_rim_area +
0.25 * q_coverage +
0.35 * q_residual +    # 最高权重，最容易导致低分
0.20 * q_axis
```

**新配置**:
```python
0.30 * q_rim_area +    # ↑ 提升到30%：面积有效性是基础
0.20 * q_coverage +    # ↓ 降到20%：覆盖率可能不完整
0.25 * q_residual +    # ↓ 降到25%：拟合噪声很正常
0.25 * q_axis          # ↑ 提升到25%：几何合理性更重要
```

**权重调整原则**:
- 面积有效性 (30%)：**最可靠**的约束，圆柱必须在合理像素范围
- 几何合理性 (25%)：**设计约束**，轴比反映观看角度的物理合理性
- 边缘覆盖率 (20%)：**可变的**，取决于图像质量和照明
- 拟合残差 (25%)：**最容易受噪声**，权重不应过高

## 三、修复前后对比

### 场景：斜视60°的圆柱

**参数**:
- axis_ratio = 0.08 (很扁)
- coverage = 0.65 (边缘覆盖65%)
- residual = 1.2 px (拟合误差1.2px)
- ellipse_area = 500 px² (在有效范围内)

**修复前**:
```
q_rim_area = 1.0       (面积有效)
q_coverage = 0.65      (覆盖率给分)
q_residual = 0.60      (残差给分)
q_axis = 0.0           ← 轴比<0.15，直接0分！

quality_score = 0.20*1.0 + 0.25*0.65 + 0.35*0.60 + 0.20*0.0
              = 0.20 + 0.16 + 0.21 + 0.0
              = 0.57  ← 还勉强 > 0.5
```

**修复后**:
```
q_rim_area = 1.0       (面积有效)
q_coverage = 0.65      (覆盖率给分)
q_residual = 0.82      (1.0 - 1.2/3.0 * 0.7 = 0.72，但有最低保留)
q_axis = 0.46          (0.4 + (0.08/0.1)*0.3 = 0.64，实际用公式)

quality_score = 0.30*1.0 + 0.20*0.65 + 0.25*0.72 + 0.25*0.64
              = 0.30 + 0.13 + 0.18 + 0.16
              = 0.77  ← 大幅提升！
```

### 场景：垂直看、边缘有遮挡

**参数**:
- axis_ratio = 0.98 (接近圆形)
- coverage = 0.45 (只有45%边缘)
- residual = 2.5 px (拟合误差较大)
- ellipse_area = 1200 px² (有效范围)

**修复前**:
```
q_rim_area = 1.0
q_coverage = 0.45
q_residual = 0.17      (1.0 - 2.5/3.0 = 0.17)
q_axis = 0.0           ← 轴比>0.95，直接0分！

quality_score = 0.20 + 0.11 + 0.06 + 0.0
              = 0.37   ← 低分，被拒发
```

**修复后**:
```
q_rim_area = 1.0
q_coverage = 0.45
q_residual = 0.42      (1.0 - 2.5/3.0 * 0.7 = 0.42)
q_axis = 0.90          (0.7 + (1.0-0.98)*3.0 = 0.76，垂直视角)

quality_score = 0.30 + 0.09 + 0.11 + 0.225
              = 0.725  ← 大幅提升！
```

## 五、后续调优指南

### 如果质量分数仍然偏低

1. **检查**修复是否正确应用
   ```bash
   grep "QUALITY_MIN_PUBLISH" arm_ws/src/vision_detection/vision_detection/config.py
   # 应该输出 0.3
   ```

2. **启用日志**查看子项分数
   ```python
   # 在 detection_node.py 中添加
   if self.debug and self.enable_frame_logs:
       metrics = live_pose.get('quality_metrics', {})
       self.get_logger().info(
           f"质量子项: area={metrics.get('q_rim_area', 0):.2f}, "
           f"coverage={metrics.get('q_coverage', 0):.2f}, "
           f"residual={metrics.get('q_residual', 0):.2f}, "
           f"axis={metrics.get('q_axis', 0):.2f}"
       )
   ```

3. **逐步提升门控**（不是一步到0.5）
   - 0.3 → 观察1小时
   - 0.35 → 观察30分钟
   - 0.4 → 观察30分钟
   - 0.45 → 观察30分钟
   - 0.5 → 最终目标

### 如果质量分数过高（都 > 0.9）

- 说明当前评分过宽松
- 可以提升权重中的严格项（如面积或轴比）
- 或进一步降低权重的容差值
